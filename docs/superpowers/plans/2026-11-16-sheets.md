# `/sheets` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tenant-aware `@mshindi-labs/google/sheets` subpath (handle with value methods + atomic `batch()` with request builders) and a `FakeSheets` test transport, replacing `@mshindi-labs/gsheets`.

**Architecture:** `createSheets(google)` → `open({tenantId, connectionId, spreadsheetId})` returns a handle. Every handle call validates input, gets a token through a shared core helper (the same path Calendar uses), and calls a `SheetsTransport` wrapped in a retry policy that is idempotent-aware (I10). Request builders are pure; `batch()` resolves tab titles to ids with at most one metadata read.

**Tech Stack:** TypeScript (strict), vitest, tsup (ESM + CJS), `@googleapis/sheets` as an optional peer (dev-pinned to `^14` for Node 18/20), `google-auth-library`.

**Spec:** `docs/superpowers/specs/2026-11-16-sheets-design.md` (read it first; this plan argues from it).

## Global Constraints

- Node `>=18.0.0`; code must not need anything newer.
- `@googleapis/sheets` peer range `>=12.0.0 <19.0.0`, optional; devDependency `^14.0.0` (v17+ needs Node 22). Loaded only through `loadPeer("@googleapis/sheets")`.
- Scope: `SERVICE_SCOPES.sheets = ["https://www.googleapis.com/auth/spreadsheets"]`.
- Default write mode `raw`; plain strings are always literal unless the caller passes `input: "user_entered"`; `{ formula }` (must start with `=`) is the only way to write a formula under `raw`.
- Only `GoogleLibError` subclasses leave the library; no access token, refresh token or client secret in any error, log or return value (I1).
- I10: `append` and `batch` are retried only on 429 / rate-limit 403 or pre-send network codes `ENOTFOUND`, `EAI_AGAIN`, `ECONNREFUSED`; any other ambiguous failure throws `SheetsWriteOutcomeUnknownError` after exactly one Google call.
- All input validation throws `InvalidSheetsInputError(field)` **before** any token fetch or transport call.
- Row/column positions in builders are 1-based inclusive; A1 utilities return 1-based bounds.
- String ranges must contain `!` (a tab); tab titles are always single-quoted with `'` doubled when the library builds A1.
- Nothing from `src/testing` may be imported by `src/sheets` or `src/core`.
- Follow repo style: double quotes, prettier, `.js` import suffixes, Conventional Commits with scope `sheets` (or `core`, `calendar`, `docs`), no AI attribution lines.

## Review Focus

1. Tab titles that need quoting (`Q1 2026`, `Bob's`, `A1`, `2026`, `Ünïcode`) — every handle method must address the right tab. → Task 7 test `quotes awkward tab titles in every method`.
2. Google omits trailing empty cells and returns no `values` for an empty tab — `getValues`/`getRows`/`findRows` must return `[]`/padded rows, never crash. → Task 7 tests `empty tab reads as []` and `ragged rows are padded`.
3. A raw Google error whose message and `config.headers.Authorization` carry the access token must not leak it through `message`, `cause`, `String(err)` or `JSON.stringify(err)`. → Task 3 test `classified errors never carry the bearer token`.
4. Empty or ragged write input (`append(tab, [])`, `update(r, [[]])`, `NaN`, `undefined` cell, `{ formula: "SUM()" }`) is rejected locally with no transport call. → Task 2 tests in `cells.test.ts` and Task 7 test `rejects bad writes before any Google call`.
5. An `append` that times out after Google applied it must be called exactly once and surface `SheetsWriteOutcomeUnknownError` (no duplicate rows). → Task 7 test `append outcome unknown is not retried`.
